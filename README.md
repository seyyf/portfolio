# SeyfOS

Seyf Mejri's portfolio is a phone. Every app on the home screen is something Seyf built; the system apps (Messages, Photos, Calendar, Settings, Files, Mail) hold the bio, gallery, career timeline, skills, CV and contact. On a phone the site *is* the phone; on tablet and desktop a framed phone floats in the middle of the page. `/resume` is the plain, printable one-page résumé.

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # production build: every route is prerendered as static HTML
npm start          # serve the production build on http://localhost:3000
```

## URLs

| URL | What |
| --- | --- |
| `/` | Lock screen (first visit) or home screen |
| `/app/<id>` | An app: `educaro`, `fripa`, `order`, `uteek`, `eprocat`, `browser`, `messages`, `photos`, `calendar`, `settings`, `files`, `mail` |
| `/app/browser?site=febal` | The in-phone browser on a site (`febal`, `aurelia`, `weedy`) |
| `/resume` | Recruiter / Focus Mode |

The OS shell lives in the `app/(os)/layout.tsx` route-group layout, so it stays mounted while the URL changes: apps open and close with animations, deep links work, and the browser back button closes apps.

## Replacing placeholders

- **Domain**: `profile.siteUrl` in `data/profile.ts` (canonical URLs, Open Graph, sitemap).
- **Live site links**: set `url` on each project in `data/projects.ts`. Empty links show as "coming soon" and hide the button.
- **Screenshots**: `public/images/projects/*.svg` are schematic placeholders. Drop in real images (PNG, JPG, WebP or SVG) and update `images` (path, alt text, width, height) for the project in `data/projects.ts`. The Browser app shows the first image as a scrolling page, so a full-length screenshot of the site works best. Photos shows every image of every project.
- **Educaro before/after**: `public/images/educaro-before.svg` and `educaro-after.svg` (also referenced in `data/projects.ts`).
- **CV**: `public/cv/Seyf-Mejri-CV.pdf` is Seyf's real CV with the phone number redacted (removed from the text layer, not just covered). To publish a new version, redact it the same way first.
- **Contact form** (Mail app): see "Contact form setup" below.
- **Open Graph image**: `app/opengraph-image.png` is a real render of the home screen. Re-render it after design changes by screenshotting the phone at 1200x630.

## Contact form setup (Formspree)

The Mail app posts to `app/api/contact/route.ts`, which validates the message and forwards it to Formspree. Messages arrive in your inbox with Reply-To set to the visitor.

1. Create a free account at [formspree.io](https://formspree.io) and a new form. Set its email to `mejri.seyf@gmail.com` (confirm it when Formspree emails you).
2. In the form's **Settings**, turn **reCAPTCHA off**. Messages are sent from the server, not a browser form, so a captcha would make Formspree reject them.
3. Copy the form endpoint (`https://formspree.io/f/xxxxxxx`) or just its ID.
4. Locally: copy `.env.example` to `.env.local` and set `FORMSPREE_ENDPOINT`, then restart `npm run dev`.
5. When deploying: add the same `FORMSPREE_ENDPOINT` variable in your host's environment settings.

Until it is set, Mail tells visitors that sending isn't set up and offers their email app with the message prefilled. If Formspree refuses a message, the server logs why (status and error code only, never the message), and the visitor gets the same fallback.

## Accessibility and performance

- The phone's back button (Android back, iOS edge swipe) works like a phone: it closes the top overlay or in-app screen first (sheets, control center, menus, photo viewer, event details), then the app. See `lib/backStack.ts`; register new overlays with `useBackLayer(open, onClose)` (the shared `Sheet` already does).
- Every gesture has a tap or keyboard alternative: swipe up to unlock or go home (buttons), long-press (right-click, or the "⋯" edit button), swipe down for the control center (tap signal/Wi-Fi), swipe between home pages (page dots, ← and →). Esc goes home.
- `prefers-reduced-motion`: transitions become quick fades; tilt, wiggle and the wallpaper motion stop.
- Each app is a separate chunk (`next/dynamic`), preloaded when you hover, focus or press its icon. No 3D, no canvas: the wallpaper is CSS, motion is transform/opacity (plus one clip-path for the app open/close).
